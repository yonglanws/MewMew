# 人格表情包管理页顺序与绑定前禁用设计

## 目标

调整人格表情包管理页的阅读顺序和交互状态，使表情包组绑定成为后续设置的前置条件，同时移除发送频率卡片中的人格头像。

## 范围

只修改 `PersonaStickerSettingsPage` 及其页面测试，不改变表情包管理首页、其他设置页、数据模型或持久化格式。

## 页面结构

人格详情页从上到下固定为：

1. 绑定的表情包组
2. 喜欢的情绪分组
3. 表情包发送频率
4. 表情使用策略

发送频率卡片保留标题、说明、三个 `StickerSendMode` 选项和帮助说明，移除 `PersonaAvatar`。

## 交互状态

使用当前页面内的 `_selectedGroupIds.isNotEmpty` 作为启用条件：

- 绑定的表情包组区域始终可操作。
- 没有绑定组时，情绪分组、发送频率、表情使用策略三张卡片显示禁用透明度，并通过 `IgnorePointer` 阻止点击、选择和文本输入。
- 至少绑定一个组后，三张卡片立即恢复可操作。
- 保存按钮始终可操作，允许用户清空绑定关系并保存。
- 禁用期间不清除已填写的发送方式、情绪偏好和自定义策略；重新绑定后恢复这些临时状态。
- 保存时仍只保存当前绑定组包含的有效情绪分组，沿用现有过滤逻辑。

## 实现边界

不新增状态字段、不改变 `PersonaStickerSettings` 或 `personaStickerBindings` 的存储结构。页面使用已有的 `Card`、`Padding`、`FilterChip`、`RadioListTile` 和 `TextField` 风格；禁用状态通过页面级组合实现，避免逐个控件遗漏。

## 验证

页面测试覆盖：

- 四个区块的顺序。
- 发送频率区块没有人格头像。
- 未绑定组时下方区块不可操作且呈灰态。
- 绑定组后下方区块恢复可操作。
- 现有页面测试和全量 Flutter 测试继续通过。
