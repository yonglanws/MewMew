# 表情包管理后续交互与缩略图优化设计

## 目标

在现有表情包管理页视觉基础上，补齐组名编辑、文件夹缩略图、无名称表情包导入和右下角主操作入口，让组列表和文件夹列表更接近其他页面的管理模式。

## 设计决策

- 不增加文件夹封面字段，不修改持久化格式。
- 文件夹缩略图动态取其子表情包列表中的第一张图片；文件不存在、路径为空或没有子表情包时，使用文件夹图标。
- `StickerItem.name` 保留用于兼容历史数据和 AI 标签匹配，但新导入不再询问用户名称，网格卡片也不展示名称。
- 表情包组支持在组详情页 AppBar 中编辑名称，沿用现有对话框和 `AppState.updateStickerGroup`。
- 表情包组列表主标题显示组名，副标题以“表情包组”为首，数量信息作为同一副标题的次级摘要。
- 新建表情包组和人格绑定均使用 `FloatingActionButton.extended`；AppBar 不再放置对应新增按钮。
- 新建文件夹对话框中，文件夹名称和场景描述之间增加统一的垂直间距。

## 页面行为

### 表情包组列表

- 右下角显示“新建表情包组”扩展按钮。
- 空状态不再提供重复的中心创建按钮，提示用户使用右下角按钮。
- 列表行标题为组名，副标题以“表情包组”开头并补充文件夹/表情包数量。
- 点击行进入组详情页。

### 表情包组详情

- AppBar 增加“编辑组名”按钮。
- 编辑成功后立即刷新当前页面标题和上级列表数据。
- 文件夹行的 leading 区域显示该文件夹第一张表情包图片的缩略图；没有可读图片时显示文件夹图标。
- 新建文件夹按钮仍位于 AppBar，避免与组列表/人格绑定的主操作混淆。

### 人格绑定

- 保留现有绑定列表和多选逻辑。
- 右下角显示“绑定人格”扩展按钮，点击后进入现有绑定选择流程。
- AppBar 不再放置额外新增按钮。

### 表情包导入与网格

- 图片选择后直接导入，不弹出名称输入步骤。
- 内部兼容名称由原文件名生成并自动去重，仅供标签匹配使用。
- 网格卡片只显示缩略图和操作菜单，不显示表情包名称。
- 删除确认文案改为“确定删除这张表情包吗？”，避免暗示名称是必填管理字段。

## 组件边界

- `_StickerEmptyState` 的操作按钮改为可选，以支持组列表只使用 FAB 的空状态。
- 新增 `_StickerThumbnail`，负责图片加载、圆角裁剪和默认文件夹图标回退。
- 组名编辑复用现有对话框模式，不新增独立页面。
- 文件夹缩略图仅由 UI 从 `AppState.stickersForFolder` 计算，不引入新的业务状态。

## 验证方案

- widget 测试验证：组列表显示组名/“表情包组”副标题、空状态依赖 FAB、人格绑定页存在右下角扩展按钮、文件夹缩略图组件在无路径时显示默认图标。
- 状态测试验证：编辑组名调用 `updateStickerGroup` 后保存新名称。
- 运行 `dart format`、目标文件 `flutter analyze`、完整 `flutter test`。
- 重点检查窄屏下 FAB、组列表副标题、文件夹缩略图和对话框字段间距不溢出。

## 非目标

- 不增加批量导入、搜索、排序、独立封面选择或新的存储迁移。
- 不改变聊天侧表情包标签匹配逻辑。
