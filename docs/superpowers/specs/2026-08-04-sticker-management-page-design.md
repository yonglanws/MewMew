# 表情包管理页视觉一致性优化设计

## 目标

优化表情包管理相关页面，使其在布局层级、组件形态、色彩、间距、空状态和操作反馈上与现有设置页保持一致，同时完整保留现有表情包组、情绪文件夹、表情包导入删除和人格绑定能力。

## 范围与约束

- 只调整 `lib/pages/sticker_management_page.dart` 中的页面结构和 UI 组件；必要时抽取该文件内的私有复用组件。
- 不修改 `AppState`、模型、持久化格式、图片导入逻辑和导航层级。
- 不新增筛选、搜索、排序或批量编辑等数据能力。
- 沿用 `AppTheme` 的 Material 3 主题令牌：淡薰衣草背景、紫色主色、`radiusLg` 大卡片、`radiusMd` 行圆角和现有按钮主题。
- 保留窄屏可用性；统计项与绑定组名在可用宽度不足时允许换行或折行。

## 设计方案

### 1. 管理首页：概览 + 分组入口

`StickerManagementPage` 继续使用 `SliverAppBar.large` 和现有返回行为。

顶部增加“表情包概览”卡片：

- 使用淡紫色容器承载标题和简短说明。
- 通过三个紧凑统计项显示表情包组、情绪文件夹、表情包数量。
- 统计项在窄屏环境下使用可换行布局，避免横向溢出。

资源区改名为“资源管理”，人格相关区保留“使用关系”。每个 section 使用一张大圆角卡片承载入口行，避免当前“入口行内部再套 Card”的嵌套感。入口行沿用设置页的 40px 柔和色块图标、标题/摘要两级文案和统一箭头。

### 2. 组与文件夹列表

表情包组列表和文件夹列表统一为单卡片分组列表：

- 每行使用图标色块、标题、数量或描述摘要和箭头。
- 文件夹行保留右侧更多菜单与删除操作。
- 新建操作继续位于 AppBar 右侧，使用现有对话框和保存流程。
- 空状态统一为图标、标题、简短说明和 FilledButton，分别用于组、文件夹和表情包网格。
- 保持现有路由与点击行为，不引入额外管理层级。

### 3. 表情网格与人格绑定

表情网格继续使用图片缩略图展示：

- 网格项沿用 `surfaceContainerLow`、圆角和稳定的图片区域。
- 名称底部对齐并保留单行省略。
- 网格项右上角增加轻量更多菜单，显式提供删除入口；长按删除保留为快捷操作。
- 空网格说明“导入图片后会显示在这里”，主按钮为“导入表情包”。

人格绑定页使用设置页同款入口行：

- 左侧显示人格图标色块。
- 中间显示人格名、绑定数量以及已绑定组名的紧凑 Chip。
- 未绑定时显示弱化提示。
- 继续使用现有多选对话框、保存流程和绑定数据。

## 组件边界

在目标页面文件内抽取以下私有组件，避免各层重复定义视觉规则：

- `_StickerOverviewCard`：首页说明与数量统计。
- `_StickerSection`：统一 section 标题与大卡片容器。
- `_StickerEntry`：设置页风格的图标入口行。
- `_StickerEmptyState`：各层级共享的空状态布局。
- `_PersonaBindingSummary`：绑定页中用于展示 Chip 和摘要的内容。

现有业务页面类（`StickerGroupListPage`、`StickerGroupPage`、`StickerFolderPage`、`PersonaStickerBindingPage`）继续保留；只替换其布局树和私有 UI 组件使用方式。

## 交互与错误处理

- 创建、导入、绑定和删除继续沿用当前异步流程。
- 文件夹和表情包删除仍通过当前已有操作入口执行，不改变删除语义；本次不新增表情包组删除入口。
- 图片无法读取时继续显示 `broken_image_outlined`。
- 用户取消图片选择时不显示错误，不产生数据变更。
- 空列表时主操作按钮应始终可见，且点击后进入现有创建/导入流程。

## 验证方案

- 先为可抽取的纯 UI 数据摘要/数量展示逻辑补充 widget 测试或最小可测试辅助逻辑；测试应先失败，再实现。
- 运行 `dart format` 检查目标 Dart 文件。
- 运行 `flutter analyze`，确认无新增静态分析错误。
- 运行 `flutter test`，确认已有测试和新增测试全部通过。
- 在至少一个窄屏尺寸下检查首页统计、绑定 Chip 和网格卡片无溢出。

## 非目标

- 不重构 `AppState` 或存储服务。
- 不改变中文文案的业务含义和现有路由。
- 不引入新的依赖或外部图标资源。
